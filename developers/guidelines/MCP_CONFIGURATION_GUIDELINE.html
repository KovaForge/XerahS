XerahS MCP Configuration Guideline

This guideline tells contributors, friends, and MCP users what must be configured to use the XerahS Model Context Protocol server correctly.

Scope Rule

The current XerahS MCP implementation is a user-desktop MCP server. It must run on the same machine whose screen, clipboard, history, settings, and uploader configuration are being controlled.

Cloudflare, GitHub Pages, and other edge/static hosts can publish discovery metadata or proxy requests to a reachable xerahs-mcp process. They do not run XerahS, cannot capture a user's screen, and cannot access that user's local history or uploader secrets by themselves.

Recommended Configuration

For ordinary users, including friends trying XerahS from an MCP-compatible host, configure local stdio mode. This is the default and safest integration path.

  1. Install a released XerahS build that includes xerahs-mcp, or build the MCP server from source.
  2. Run the MCP client on the same desktop account that can use XerahS capture, clipboard, and upload features.
  3. Configure the MCP client to launch xerahs-mcp --mcp.
  4. Grant OS screen capture, window capture, clipboard, and accessibility permissions where the platform requires them.
  5. Configure XerahS uploader destinations locally if the user wants upload tools to return URLs.

Generic MCP Client JSON

Use the installed path on the user's machine. Do not point ordinary users at mcp.xerahs.com. 

{
  "mcpServers": {
    "xerahs": {
      "command": "C:/Program Files/XerahS/xerahs-mcp.exe",
      "args": ["--mcp"]
    }
  }
}

Development Build JSON

{
  "mcpServers": {
    "xerahs": {
      "command": "C:/Users/<user>/source/repos/KovaForge/XerahS/src/tools/XerahS.McpServer/bin/Release/net10.0/xerahs-mcp.exe",
      "args": ["--mcp"]
    }
  }
}

Build and Smoke Test

Build the MCP server from the repository root:

dotnet build .\src\tools\XerahS.McpServer\XerahS.McpServer.csproj -c Release

Run the focused MCP tests:

dotnet test .\src\tools\XerahS.McpServer.Tests\XerahS.McpServer.Tests.csproj --configuration Release

Smoke test stdio initialization and tool discovery:

$exe = ".\src\tools\XerahS.McpServer\bin\Release\net10.0\xerahs-mcp.exe"
$input = @(
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}',
  '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}',
  '{"jsonrpc":"2.0","id":3,"method":"shutdown","params":{}}'
) -join "`n"
$input | & $exe --mcp

A successful smoke test returns an initialize result with server name xerahs and a tools/list result that includes capture, annotation, upload, history, workflow, and settings tools.

HTTP Mode

HTTP mode is optional. Use it only when the operator has a user-controlled desktop session or dedicated desktop/VM host running the real XerahS runtime. 

xerahs-mcp --mcp-server --transport http --port 7890
Endpoint Purpose
POST /mcp/ JSON-RPC MCP requests.
GET /mcp/events/ Server-Sent Events notifications and heartbeats.
GET /health Health check for the running HTTP process.

HTTP transport requires Authorization: Bearer <mcp-api-key>. The key is stored in ApplicationConfig.McpApiKey and can be generated or copied from XerahS settings under Integration - MCP Server.

Public Manifest and Cloudflare

The public manifest may be available at https://xerahs.com/.well-known/mcp/manifest.json. It can advertise an optional HTTP endpoint such as https://mcp.xerahs.com/mcp/.

The public manifest and Cloudflare Worker are not enough to use XerahS MCP. They are discovery/proxy infrastructure only. The endpoint works only when it has been configured to forward to a running xerahs-mcp --transport http backend.

Scenario Correct configuration
Friend wants to use XerahS MCP on their desktop. They install XerahS locally and configure xerahs-mcp --mcp in their MCP client.
Contributor wants to test the repo build. They build the MCP project and point the MCP client at the repo's Release executable.
Operator wants a public HTTP endpoint. They run xerahs-mcp --transport http on a desktop/VM backend and configure Cloudflare to proxy to it.
No desktop/runtime backend exists. Do not advertise the HTTP endpoint as functional. Use local stdio mode.

Security Rules

  • Never publish a user's MCP API key in docs, issues, logs, screenshots, commits, or chat transcripts.
  • Do not expose HTTP mode to the internet without bearer authentication and a deliberate backend host.
  • Do not imply that Cloudflare can run screen capture, clipboard, history, settings, or uploader tools without a XerahS desktop runtime.
  • Use local stdio mode unless there is a specific reason to operate a network endpoint.

Troubleshooting

Symptom Likely cause Action
Client cannot start MCP server. Wrong executable path or missing build. Verify the command path and build/install XerahS.
tools/list returns no XerahS tools. Client is not launching xerahs-mcp --mcp. Check MCP client JSON and restart the client.
Capture tools fail. No interactive desktop session or missing OS permissions. Log into the desktop and grant screen/window capture permissions.
Upload tools fail. No local uploader destination configured. Configure upload destinations in XerahS on the same user account.
Public /mcp/ returns backend configuration errors. Cloudflare has no reachable xerahs-mcp HTTP backend. Use local stdio mode or configure a real desktop/VM backend.
