- **Reported by**: QA Tester (not developer)
- **Branch**: `develop` (HEAD: `dd19a5b0`)

## Description

All configured hotkeys are non-functional. Pressing any registered hotkey combination produces no response from the application. The application's DBus-based global shortcuts portal (`org.freedesktop.portal.GlobalShortcuts`) appears to register hotkeys, but the [Activated](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#530-568) signal is never delivered to the application.

---

## Steps to Reproduce

1. Launch the application on Wayland/KDE Plasma.
2. Configure at least one hotkey (e.g. `PrintScreen` for full-screen capture).
3. Press the configured hotkey.
4. Observe: nothing happens. No capture is triggered, no logs show the hotkey being received.

## Diagnostic Evidence

### Key Finding: [OnActivated](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#530-568) signal never fires

Enhanced `[HotkeyDiag]` logging was added to [WaylandPortalHotkeyService](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#87-120). After the session was running and hotkeys were pressed, **zero `[HotkeyDiag] OnActivated` log lines appear in the output**. This means the XDG Global Shortcuts portal's [Activated](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#530-568) DBus signal is not being received by the application at all — the hotkeys are registered on the portal side but the signal path back to the app is broken.

### Root Cause: DBus Connection Disposed by Portal Screenshot Cancel Flow

The session log shows the following sequence:

1. Hotkeys are registered and the portal session is created normally.
2. An `ActiveWindow` screenshot portal request is cancelled by the user (`Response=1`).
3. Immediately after the cancel, the DBus connection is disposed:

```

Object name: 'Tmds.DBus.Connection'.)
```

4. This triggers the same fatal `TaskCanceledException` crash chain seen in previous reports:

## Evidence Screenshots Are Working (via Portal)

Interestingly, screen capture via hotkeys does partially work — the logs show two successful captures triggered by hotkeys (one `PrintScreen` full-screen, one `RegionCapture`) completing successfully and being saved to disk:

```
2026-03-24 04:09:49.355 - Image saved: .../20260324T0409_XnC7zSPGYB.png
2026-03-24 04:09:53.356 - Image saved: .../20260324T0409_4brjYsgdND.png
```

This confirms hotkeys **were working initially**. They stop working after the first DBus error occurs (triggered by a portal cancellation or the stop-button crash from a prior recording session).

## Root Cause Summary

The [WaylandPortalHotkeyService](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#87-120) and the `LinuxScreenCaptureService` share the same `Tmds.DBus` session bus connection infrastructure. When any portal operation (screenshot, recording stop, etc.) causes a DBus error, the connection is torn down — silently killing the hotkey [Activated](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#530-568) signal subscription. Because exit code is `0`, the application does not crash visibly, but hotkeys stop working for the rest of the session.

## Suggested Fix Direction

1. **Isolate the DBus connections**: [WaylandPortalHotkeyService](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#87-120) should own its own dedicated `Tmds.DBus.Connection` instance, completely separate from any connection used by capture/screenshot services. A crash on the capture connection must not affect the hotkey subscription.

2. **Reconnect on disconnect**: Add a reconnect/re-subscribe mechanism to [WaylandPortalHotkeyService](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#87-120) — if the DBus connection is lost (detected via [OnPortalWatchError](file:///home/mathew/Documents/GitHub/ShareX%20Team/XerahS/src/platform/XerahS.Platform.Linux/Services/WaylandPortalHotkeyService.cs#584-588)), automatically re-create the session and re-register all hotkeys.

3. **Fix the `Observer.Dispose` crash**: The `Tmds.DBus.Protocol.DBusConnection.Observer.Dispose()` method calls `AvaloniaSynchronizationContext.Send()`, which throws a `TaskCanceledException` when the dispatcher is shutting down. This call path should be wrapped in a `try/catch` to prevent an unhandled exception from crashing the thread.
