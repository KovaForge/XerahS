## Summary

May 11 focused on making the uploader and release pipeline more reliable on `develop`. The OpenClaw toolchain gained stricter validation and clearer error reporting around generated CLI JSON, the S3 plugin moved credential handling onto shared secret aliases that survive provider churn and upstream merges, and Windows capture cleanup tightened cursor-replacement disposal. In parallel, the Linux packaging track finalized Flathub metadata, synced the AppStream release version, and closed the remaining release-verification paperwork for `v0.22.256`.

## Features

- XerahS: Added direct `upload-text` support to the generated OpenClaw CLI surface so plugin workflows can send text payloads without relying on indirect file-based paths.

## Fixes

- XerahS: Tightened OpenClaw upload validation so reported upload URLs must be real HTTP(S) targets, reducing the chance of accepting malformed tool output during plugin execution.
- XerahS: Updated the uploader bootstrap and doctor flows to emit structured CLI JSON output, making diagnostics and automation consumers less dependent on loosely formatted stdout/stderr parsing.
- XerahS: Improved generated OpenClaw CLI handling so JSON output is validated, raw CLI errors are printed back to callers, preserved result payloads survive the exporter pipeline, and validation failures describe the exact malformed fields instead of collapsing into vague exporter failures.
- XerahS: Hardened uploader report validation around OpenClaw responses so invalid bootstrap or report payloads are rejected earlier and surfaced more predictably.
- XerahS: Shared Amazon S3 access-key credentials through keychain-backed secret-store aliases, then preserved that credential path through the same-day upstream merge so saved S3 access keys are less likely to break during provider identity changes.
- XerahS: Hardened GDI cursor replacement cleanup in the Windows capture path and backed the fix with updated tests to reduce resource-leak regressions in modern capture flows.
