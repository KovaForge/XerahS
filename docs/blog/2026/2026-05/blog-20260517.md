## Summary

May 17 UTC+8 was a broad reliability pass across XerahS, covering assistant OCR history cleanup, toast-window behavior, FFmpeg process handling, updater behavior, and embedded editor save recovery. The main product repository carried most of the day's work, while ShareX.ImageEditor contributed one supporting save-destination fix and XerahS.Editor had no qualifying commits in the same UTC+8 window.

## Features

- XerahS: `KFIP0009` was added to capture planned X/Twitter screen capture workflow enhancements, giving the day one contributor-facing planning artifact even though no new end-user feature shipped from it yet.

## Fixes

- XerahS: Assistant history search now ignores OCR content that belongs to screenshot files already deleted from disk, preventing stale capture text from continuing to match later searches.
- XerahS: The assistant OCR search fix added regression coverage around deleted indexed captures so the stale-result case stays locked down by tests.
- XerahS: The Windows updater launch path was adjusted to run silently with `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE`, suppressing message boxes and avoiding an unnecessary forced restart prompt during updater execution.
- XerahS: Toast notifications now emit a zero-opacity state before fade-close, stay within screen bounds on multi-monitor setups, and resume fading correctly after the context menu closes before the toast duration expires.
- XerahS: FFmpeg forced-close now kills the full process tree instead of leaving child processes behind, and FFmpeg video probe paths are now escaped correctly when building commands.
- XerahS: Embedded editor save flows now recreate missing save destinations before writing out changes, aligning the app with the supporting ShareX.ImageEditor destination-file fix.
