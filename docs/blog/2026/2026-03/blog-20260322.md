## Summary

March 22 was a focused quality-of-life fix day. A single targeted commit addressed a UX rough edge that was exposed after the after-capture workflow changes: when a user cancels the `AfterCaptureWindow`, a toast notification was still being displayed as if the task had completed successfully. The fix cleanly propagates a cancellation signal through the job processor pipeline so that no success notifications fire when the after-capture step is abandoned.

## Features

- No new user-visible features shipped on this day. All work was corrective.

## Fixes

- XerahS: The `AfterCaptureWindow` cancellation now correctly suppresses the post-task toast notification (`51dc50ae`). Previously, cancelling the window mid-flow still triggered the "task complete" toast, misleading users into thinking their capture had been uploaded or processed. The fix threads a cancellation state through `IJobProcessor`, `FinalizationStage`, `CaptureJobProcessor`, and `UploadJobProcessor` so all downstream stages see the cancellation and skip toast emission.
