# XerahS Daily Blog Draft - 2026-03-23

Date: 2026-03-23
Time Zone: UTC+8
Status: Draft

## Summary

March 23 mixed two Linux parity fixes in XerahS with a much larger editor architecture push spanning both XerahS documentation and ShareX.ImageEditor implementation. ShareX.ImageEditor delivered a strong feature wave with remove-background, edge-feather, inner-shadow, and EffectBrowser polish, then closed the day by landing the first IEIP0004 schema-driven refactors for adjustments, manipulations, drawings, and the browser catalog itself. XerahS documented that shift as an implemented proposal while keeping host behavior aligned on Linux, and XerahS.Editor was checked with no matching UTC+8 commits.

## Features

- ShareX.ImageEditor: New image-editing capabilities landed in a cluster. Remove background (`9447b8e`) introduced a full background-removal pipeline, then a follow-up (`cfc85c1`) placed it in the right UI/category path. The same stretch also added Edge Feather (`9fa27d3`) and a new Inner Shadow filter (`4d1ea16`, `6c1eaa1`) with numeric offsets and a larger size ceiling for stronger looks.
- ShareX.ImageEditor: EffectBrowser and effect discovery became easier to use. Category headers gained a hint icon and tooltip (`81887ef`), recent effects can now be removed with a right-click (`52de63c`), spotlight mementos were enabled with stronger defaults (`370fae9`), and nebula rendering was tuned for better twinkle and streak output (`4a439db`).

## Fixes

- XerahS: The Linux "Add from Catalog" path was fixed by dispatching modal-open state changes onto the Avalonia UI thread (`326d104`). This addressed the Linux/X11 case where the command ran but the modal overlay failed to repaint, making the button appear to do nothing even though it still worked on Windows.
- XerahS: Overlay capture behavior was brought back into line with the shared `UseTransparentOverlay` setting (`4688c133`). The common Linux path stopped forcing the fast overlay unconditionally, so transparent overlay preference once again drives the host capture experience in the same way across platforms.

## Build and Tooling

- XerahS: IEIP0004 was created and then finalized as an implemented architecture proposal (`999f6dcf`, `eb3dcc96`). That documentation does not describe a speculative future anymore; it records the move toward one schema-driven contract across adjustments, manipulations, drawings, and filters.
- ShareX.ImageEditor: The first wave of that implementation landed the same day. The editor unified the image-effect schema infrastructure (`6f27900`), migrated adjustment dialogs (`6bef4d9`), manipulation and drawing dialogs (`70e16f3`), and routed the EffectBrowser through a unified catalog registry (`f14289e`), giving contributors a shared path for future effect registration and dialog generation.
