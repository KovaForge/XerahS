# XerahS Daily Blog Draft - 2026-03-30

Date: 2026-03-30
Time Zone: UTC+8
Status: Draft

## Summary

March 30 UTC+8 brought a focused XerahS push around Linux recording reliability and editor infrastructure, alongside an ongoing ShareX.ImageEditor effects expansion. XerahS shipped partial portal recording recovery for externally terminated sessions, shared the editor wallpaper services across all host types as part of the IEIP0006 follow-through, and published the XIP0059 proposal to document the recovery behaviour. ShareX.ImageEditor kept its rapid effects cadence going, adding a candy cane border, a hair-simulation filter, eleven more creative image effects across two batch commits, command-line image loading, and a new application icon — which XerahS also adopted on the same day. The editor project also renamed its loader entry-point to the cleaner `ShareX.ImageEditor.App` name.

## Features

- XerahS: Portal recording sessions that are terminated externally (for example, when a compositor drops the portal connection mid-capture) can now recover whatever was written before the session ended. The new recovery path detects the partial output and hands it back to the task system instead of silently discarding incomplete footage (`b892e7af`).
- XerahS: The wallpaper services that were moved into the editor during IEIP0006 are now shared across all host types rather than being configured per-platform. This allows both the Windows and Linux desktop hosts to access the same editor-resident wallpaper prewarm and format-conversion pipeline without each host reimplementing its own path (`9a5be6e3`).
- ShareX.ImageEditor: The `ShareX.ImageEditor.App` entry point received full command-line image loading support so the standalone editor can be launched with a file path as an argument, opening the image directly instead of presenting a blank canvas (`5ecd8198`).
- ShareX.ImageEditor: The standalone editor application gained a dedicated application icon included in the project, replacing the generic default. XerahS also replaced its own application icon with the same new asset on the same day (`6d4d2688`, `8cba6484`).
- ShareX.ImageEditor: Seventeen new image effects arrived across two and a half batch commits. The additions span creative filters such as Candy Cane Border, a hair-simulation effect called FakeHair, and a rich collection of drawing and compositional filters including Neon Glow, Vignette, Color Jitter, Pixelate, and others (`5fa8e79a`, `cb9e176e`, `06b2c91c`, `dcb81628`).

## Fixes

- ShareX.ImageEditor: Exit confirmation in the standalone editor is now only displayed in release builds. The `DEBUG` build suppresses the dialog so developers can iterate quickly without having to dismiss a confirmation prompt on every test run (`579551cf`).

## Build and Tooling

- XerahS: XIP0059 was published to document the partial recording recovery mechanism — its expected trigger conditions, the recovery algorithm, and the failure modes that the new path is designed to handle (`af4fe0a9`).
- ShareX.ImageEditor: The loader project was renamed from `ShareX.ImageEditor.Loader` to `ShareX.ImageEditor.App`, aligning the project name with the icon, the entry-point binary, and the proposal documentation that referred to the module as `ImageEditor.App` (`dcc9d8a2`).
- ShareX.ImageEditor: The Candy Cane Border effect's border-width parameter was migrated to use `IntSlider` instead of a free numeric input, giving the effect a more polished in-panel editing experience (`55476135`).
- ShareX.ImageEditor: The wallpaper service centralisation that XerahS drove at the host level also landed as a complementary refactor in the editor's host layer, ensuring the two sides of the IEIP0006 boundary present a consistent interface (`959bc540`).
