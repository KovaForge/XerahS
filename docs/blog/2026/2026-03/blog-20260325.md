# XerahS Daily Blog Draft - 2026-03-25

Date: 2026-03-25
Time Zone: UTC+8
Status: Draft

## Summary

March 25 was a consolidation day centered on the IEIP0004 unified-effect branch. XerahS repointed its ShareX.ImageEditor submodule at that refactor branch, pulled in a steady stream of parity and auto-crop fixes, simplified upload destination recovery, and cleaned up the XIP proposal set while also formalizing the rule that XerahS commit prefixes must stay aligned with `Directory.Build.props`.

ShareX.ImageEditor spent the same day restoring user-facing parity with `develop` inside the unified effect browser, undoing the previous day's preview-path experiment, strengthening image ownership and preview handling around `SKBitmap`, and shipping a more capable step/number annotation control with interactive tail support. XerahS.Editor had no matching commits on this UTC+8 day.

## Features

- ShareX.ImageEditor: Number annotations gained a dedicated `StepControl` and explicit tail support (`6c73b26`, `d90e0cc`). The editor now stores and transforms tail points alongside the annotation body, renders them through a purpose-built control instead of the older grid-based visual, and supports interactive tail dragging so numbered callouts can point at the exact detail they describe.
- ShareX.ImageEditor: The unified effect browser moved much closer to `develop` parity. Labels and acronym handling were aligned with the existing catalog metadata (`e4c51a0`), host shortcuts and filter behavior were restored (`bce6b79`, `ee7ac64`), border and remove-background entries were recategorized to match established groupings (`ad0357f`), and the temporary duplicate-filter workaround could then be removed (`1aac29b`).
- XerahS / ShareX.ImageEditor: Host integration work became a feature delivery path of its own. XerahS first repointed the submodule at the IEIP0004 refactor branch (`f49f8cb2`) and then repeatedly bumped it through parity, crop-dialog, and auto-crop fixes (`e5acc011`, `6d4a3939`, `9c74ef23`, `9767ecc2`, `4377f217`, `cdb03b49`, `521eb39d`, `7354a04f`) so desktop builds could consume the refactor branch's current UX instead of staying on an older snapshot.

## Fixes

- ShareX.ImageEditor: The previous day's `Effect apply: always compute fresh result from source snapshot` change was partially unwound (`c6cc4f0`) to restore the established `ApplyEffect(Func)` preview commit path. That rollback reduced risk while the branch continued absorbing larger catalog and host-integration changes.
- ShareX.ImageEditor: Several integration defects were corrected on the refactor branch. The effect browser was made lazy-loaded and the preview/image path was shifted to validated `SKBitmap` copies to avoid unsafe bitmap ownership and stale preview issues (`1d63d81`), branch-only event subscriptions were removed so `EffectBrowserPanel` matched the real API surface again (`49cf9e4`), and auto-crop apply behavior was repaired in the editor itself (`f751baa`) before XerahS pulled that fix via submodule (`7354a04f`).
- XerahS: Upload destination recovery was simplified (`33beb845`). Instead of mutating saved uploader instance IDs when a configured destination disappears, the app now falls back to the default instance directly and removes the extra persistence-and-repair path from capture upload processing.

## Build and Tooling

- XerahS: The proposal set was consolidated aggressively (`62ff53d3`). Several overlapping or superseded XIPs were renamed, merged, or removed so the documentation tree reflects the active roadmap more cleanly and avoids keeping duplicate architectural proposals in parallel.
- XerahS: Repository workflow guidance now explicitly pins XerahS commit prefixes to the root app version until `Directory.Build.props` changes (`9777ead6`). That documentation fix closed the gap exposed by some earlier March 25 commits that briefly used higher patch numbers even though the app version was still `0.20.18`.
- XerahS: IEIP0004 gained an additional lessons-learned documentation update (`c920beee`), recording what the host/effect-browser integration had already taught the branch.
- ShareX.ImageEditor: The refactor branch synced with `develop` twice (`36ad9b3`, `e02e402`) and refactored crop-dialog plumbing through a shared `ShowCropImageDialog` path (`70a0c28`), keeping the branch closer to mainstream editor behavior while parity fixes landed around it.
