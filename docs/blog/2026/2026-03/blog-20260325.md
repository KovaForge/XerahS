## Summary

March 25 focused on pulling the IEIP0004 image-effects branch back toward develop parity while keeping XerahS host integration grounded in the same upstream fixes. ShareX.ImageEditor restored missing effect-browser behavior, moved more preview and image-handling paths onto safer `SKBitmap` flows, and landed a substantial annotation upgrade for numbered steps before closing the day with event-wiring and auto-crop apply repairs. In the XerahS repo, the day also simplified upload-destination recovery behavior, cleaned up the XIP proposal set, and repeatedly bumped the ImageEditor pointer so the host tracked the editor-side fixes closely.

## Features

- ShareX.ImageEditor: Number and step annotations gained a dedicated `StepControl`, interactive tail dragging, better hit-testing, and transform-aware tail updates, then widened the rendered tail for better visibility. This turned numbered callouts into a richer editing surface instead of a simple text-in-circle visual (`6c73b26`, `d90e0cc`).
- ShareX.ImageEditor: The effect browser moved toward a more resilient host architecture. The browser panel is now created lazily, dialog lookup prefers registered factories before schema fallback, and preview/image-loading paths were moved onto validated `SKBitmap` handling so effect previews and editor-core synchronization use safer bitmap ownership rules (`1d63d81`).
- XerahS / ShareX.ImageEditor: The IEIP0004 branch regained more of develop's effect-browser behavior across host shortcuts, effect labels, filter rows, categories, and crop-dialog plumbing. XerahS tracked those upstream improvements through a series of submodule bumps so the desktop host stayed aligned with the evolving editor API (`f49f8cb2`, `e5acc011`, `6d4a3939`, `9c74ef23`, `9767ecc2`, `4377f217`, `cdb03b49`, `bce6b79`, `ee7ac64`, `ad0357f`, `1aac29b`, `70a0c28`, `c6cc4f0`).

## Fixes

- XerahS: Upload destination recovery was simplified by removing the old "heal and persist" path. When a configured uploader instance is missing, the app now resolves to the default instance instead of trying to write repaired IDs back into settings from capture and upload processors (`33beb845`).
- ShareX.ImageEditor: Late-day integration fixes removed invalid `EffectBrowserPanel` event subscriptions that had drifted from the actual panel API, which got the unified branch compiling cleanly again (`49cf9e4`).
- ShareX.ImageEditor: Auto-crop apply behavior was repaired in the unified effects host, and XerahS immediately pulled that fix through the submodule pointer so the host-side crop flow matched upstream behavior again (`f751baa`, `7354a04f`).

## Build and Tooling

- XerahS: The ImageEditor submodule was pointed at the IEIP0004 refactor branch early in the day and then updated several times as upstream parity and crop-dialog fixes landed. That kept the publishing repo synchronized with real editor changes instead of documenting a stale integration state (`f49f8cb2`, `e5acc011`, `6d4a3939`, `9c74ef23`, `9767ecc2`, `4377f217`, `cdb03b49`, `7354a04f`).
- XerahS: The XIP proposal set was consolidated aggressively. Several proposal files were renamed for clarity, superseded drafts were removed, and a broader cleanup pass reduced proposal sprawl across the docs tree (`62ff53d3`).
- XerahS: Commit-message guidance was brought back into line with `Directory.Build.props`, closing the gap that had allowed docs and submodule commits to drift above the repo's declared version (`9777ead6`).

## Notes

- Much of March 25 was integration debt paydown around IEIP0004 rather than net-new end-user functionality. The effect browser and crop flow needed several parity and wiring passes before the unified branch was stable enough to keep moving.
- The XerahS-side upload change deliberately removed persistence logic rather than adding more recovery code. That reduces surprise settings writes, but it also means future uploader-migration work should be explicit about how missing instances are surfaced and resolved.
- XIP cleanup happened alongside runtime work, but several proposal topics remained in motion. The documentation tree was being actively curated, not treated as settled design.
