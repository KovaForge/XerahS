## Summary

Balanced ImageEditor GPU optimization work with Linux watch-folder and save-path reliability fixes, making it safer to run background automation while we push the editor harder with hardware acceleration experiments.

## Features

- Wired an ImageEditor GPU Option B worker into XerahS so the app can begin experimenting with hardware-accelerated image effects through SkiaSharp, setting the stage for faster editing flows.
- Added a Zoom to Fit option to the ImageEditor zoom picker dropdown, improving ergonomics when jumping between very large and very small captures.

## Fixes

- Fixed SaveRequested/SaveAsRequested wiring for both embedded and standalone editor hosts so edits are consistently persisted regardless of how the editor is launched.
- Improved uploader behavior by falling back to File-category instances when no Image uploader is configured, preventing capture flows from failing silently.
- Ensured Linux watch-folder behavior remains compatible with legacy `watchfolder.service` configurations while the new daemon support evolves.
- Continued to update the ImageEditor submodule with targeted fixes and refactors to keep GPU and save-path behavior aligned.

## Build and Tooling

- Updated ImageEditor and related XIP0042 documentation around SkiaSharp hardware acceleration, capturing the trade-offs and architecture behind GPU Option B.
- Synced CI and project wiring so ImageEditor changes land cleanly in XerahS without breaking existing watch-folder or save workflows.
