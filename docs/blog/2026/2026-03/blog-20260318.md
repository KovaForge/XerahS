# XerahS Daily Blog Draft - 2026-03-18

Date: 2026-03-18
Time Zone: UTC+8
Status: Draft

## Summary

March 18 ended up broader than the first pass of this draft. XerahS tightened recorder and Task Settings image-effect workflows, then spent the rest of the day migrating the desktop shell to native Fluent theming, fixing a Linux dialog visibility regression, and hardening cross-platform Send To behavior across Windows, Linux, and macOS.

ShareX.ImageEditor advanced in parallel by adding a text watermark effect and continuing a large editor-style consolidation, which XerahS consumed through multiple submodule updates. XerahS.Editor was checked for this UTC+8 day and did not contribute any commits.

## Features

- XerahS upgraded Task Settings image-effect authoring by reusing the refactored ImageEditor effect browser as a modal picker and by bringing ImageEditor-style property editing and preview heuristics into workflow configuration.
- ShareX.ImageEditor added a text watermark effect with token expansion, placement and styling controls, preview/apply hooks, and a dedicated dialog so annotated text watermarks can be composed directly in the editor.
- XerahS migrated more of the desktop shell to native Fluent theming and took ownership of the `HostIcons` surface inside `XerahS.UI`, which keeps host-specific navigation and theme decisions in the app while the shared editor library stays app-agnostic.

## Fixes

- Fixed recorder workflow correctness in XerahS by prompting for a custom region when none is configured, persisting the selected bounds, routing recorder-start workflows back to the saved last region, wiring `StopScreenRecording` through active session signaling, and extending CLI duration auto-stop coverage across recorder job variants.
- Restored Task Settings Add Effect enumeration so supported effects without parameterless constructors appear again, then removed workflow image-settings dead space, normalized effect property controls to the XerahS theme, and fixed Linux image-effect browser dialogs so they remain visible while editing.
- Hardened XerahS desktop reliability by preventing a startup crash in the new native theme resources and by making Windows, Linux, and macOS Send To integration behave more explicitly across upload and entry-generation flows.
- Defaulted clipboard monitoring to disabled for new configs and hardened plugin-folder cleanup so bundled and user plugin roots are cleaned consistently without unsafe foreground deletion behavior.

## Build and Tooling

- ShareX.ImageEditor centralized editor presentation infrastructure by moving shared control styles into `ShareXStyles.axaml`, inlining typography resources into `ShareXTheme.axaml`, scoping the style include to `EditorView`, and adding reusable popup, chevron, sidebar, and overlay animation classes.
- XerahS updated the `ShareX.ImageEditor` submodule in multiple steps to pick up the editor popup/style refactor first, then the `HostIcons` removal, and finally the follow-up visual polish that widened sidebars and replaced hardcoded dialog colors with shared themed controls.
- XerahS's native Fluent theme migration removed a large amount of custom theme resource surface area while keeping app views aligned with the newer host styling model.
- Test/build maintenance on Linux excluded Windows-only clipboard tests from non-Windows runs so cross-platform solution builds stop pulling in intentionally empty Windows platform code.
