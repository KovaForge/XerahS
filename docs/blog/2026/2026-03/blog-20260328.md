## Summary

March 28 UTC+8 was the busiest single day of the week, spanning a clean v0.21.0 release, a substantial Linux portal and Wayland hardening push, a changelog and blog-automation layer, and cross-cutting ShareX.ImageEditor UI work. The day began with the v0.21.0 CI release commit, then the changelog was built and condensed from historical commits. ShareX.ImageEditor repaired overlay crop integration and tightened empty-state actions; XerahS immediately pulled the fixes through and adjusted host-side empty-state handling. The afternoon brought the day's most architecturally significant work: Linux overlay window preselection was restored, native Wayland window snapping helpers were added, window enumeration was hardened via EWMH, and the xdg-desktop-portal fallback flow was fixed to recover properly after a GNOME area-capture denial. A scheduled workflow was added to keep blog drafts in sync on `develop`, and the changelog skill was extended with automatic consolidation support.

## Features

- XerahS: Native Wayland window snapping helpers were added so snapping can work directly through Wayland protocols instead of always falling back to X11-emulated EWMH moves. XIP0058 was updated to document the Wayland parity goals and the remaining limitations on pure Wayland desktops (`e04ba295`, `ef17ff47`).
- XerahS: Linux overlay window preselection was restored after a regression in the portal-based overlay flow that had broken window highlighting and selection in the region-capture UI on Linux (`a81e83d3`).
- XerahS: Blog-maintenance automation became a committed repo capability. A scheduled GitHub Actions workflow runs daily at `16:00 UTC` on `develop`, calls the `draft-blog-post` wrapper with `-IncludePreviousDay`, and commits the current and previous UTC+8 day draft files when they are absent (`1a9e1eb4`).
- XerahS: Changelog tooling became more opinionated and useful for release work. The `update-changelog` skill and its backing script can now consolidate similar commits automatically, fitting the same day's changelog rewrite toward grouped, thematic entries (`4ba4de68`, `81354e19`, `e34b26a1`).

## Fixes

- XerahS: Portal reentry was prevented after a Linux overlay capture session completes. Without this guard, the overlay could re-enter the portal flow on teardown and trigger a second capture session unintentionally (`51846d3e`).
- XerahS: The xdg-portal fallback path was fixed so that after GNOME denies an area-capture request, the capture service correctly falls back to the GNOME-native region capture path instead of erroring out. A guard test was added to cover the fallback behaviour (`1171a059`, `79e0b5fe`).
- XerahS: Linux window hover enumeration was hardened using EWMH window list queries to find hovered desktop windows more reliably across compositors (`d0eb2523`).
- XerahS: Wayland portal input service initialisation was moved to be asynchronous so that UI startup is no longer blocked by the portal handshake on session open, preventing a perceptible freeze on Wayland desktops (`15c0cc54`).
- XerahS: Linux window snapping support was clarified so the UI no longer presents snapping affordances in contexts that the current Wayland session cannot support (`beda80f0`).
- ShareX.ImageEditor / XerahS: Empty-state actions were tightened so pin and upload affordances are disabled when no image is loaded. The fix landed upstream in ShareX.ImageEditor first, then XerahS updated its submodule pointer and host-side empty-state handling so the desktop app no longer advertises invalid actions on a blank editor surface (`f000e96`, `05b24ba1`, `334822f7`).
- ShareX.ImageEditor: Overlay crop integration and the editor build were repaired together, undoing a broken interaction-controller path and wiring the editor view back into the corrected crop flow (`12c9331`, `2a39990`).
