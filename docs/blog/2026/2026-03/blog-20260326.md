# XerahS Daily Blog Draft - 2026-03-26

Date: 2026-03-26
Time Zone: UTC+8
Status: Draft

## Summary

March 26 split across three clear tracks in XerahS and ShareX.ImageEditor: uploader infrastructure, editor-effects integration, and Linux recording hardening. XerahS added the shared multipart upload abstractions, implemented S3 multipart upload support with tests, refined the custom-uploader workflow and documentation around destination fallback, and then closed the day by hardening Wayland recording pause behavior and video-editor launch policy. ShareX.ImageEditor, meanwhile, shipped immediate browser-effect execution and host-routed browser shortcuts, added file-path support to displacement maps, and merged the broader IEIP0004 unified schema branch back into develop before the submodule was updated in XerahS.

## Features

- XerahS: Multipart uploads became a first-class capability instead of an S3-specific one-off. The core uploader layer now has shared planning, retry, progress, result, and part-range abstractions, Amazon S3 gained a concrete multipart uploader with new config/UI support, and the test suite added focused coverage for the new upload path (`1033f4d4`, `af844088`, `66383717`).
- XerahS: Custom uploader and destination UX kept moving forward. The task settings UI now explains the difference between automatic and fixed upload targets, the custom uploader flow hides the legacy ShareX import after first run, and XIP0056 was expanded around instance creation, save-back, `.sxcu` metadata, and the new "Save to Plugins" wording (`230bdf02`, `c014052b`, `89f6d0a5`, `53f6eea0`, `96e99345`).
- ShareX.ImageEditor / XerahS: The IEIP track advanced in two directions at once. ShareX.ImageEditor added immediate browser effect execution, routed browser shortcut actions through the host, added file-path support to displacement maps, and then merged the large unified-schema branch into develop; XerahS followed by switching the submodule back to `develop`, updating the pointer, and recording the next redesign proposal in `IEIP0005` (`dc641a1`, `645ea00`, `efe2165`, `be160ff`, `31348f9f`, `b61ea536`, `e06a47ed`, `39c9757c`).

## Fixes

- XerahS: Provider-catalog modal opening was centralized behind a shared service so platform-specific input and backdrop timing no longer closes the catalog immediately on some hosts (`be448902`).
- XerahS: Recording controls now respect platform capabilities more explicitly. Unsupported pause actions are gated on Wayland-facing recording paths, and a new launch-policy layer hardens when and how the video editor is invoked from UI and headless flows on Linux Wayland (`2a6a0b50`, `06659ec3`).
- ShareX.ImageEditor: Browser-triggered effects became more trustworthy in the merged IEIP flow. Immediate effects now execute immediately, host shortcut actions are routed through the host instead of bypassing it, and displacement-map effects can resolve file paths directly instead of assuming only in-memory inputs (`dc641a1`, `645ea00`, `efe2165`).

## Build and Tooling

- XerahS: The documentation stream was unusually active alongside the code work. The repo restored XIP0054 for S3 multipart uploads, added a dedicated architecture note about upload destination fallback behavior, corrected the `TryUploadWithFallback` XML summary, and wrote hardening notes for hotkeys plus video-recording pause/stop behavior (`126a07f1`, `ac9e42e0`, `73ad1148`, `612d547c`).
- XerahS / ShareX.ImageEditor: Line-ending policy and submodule tracking were tightened up around the ImageEditor merge. XerahS enforced LF line endings in the publishing repo, ShareX.ImageEditor briefly did the same and then reverted the standalone enforcement commit in favor of the merged branch state, and the XerahS submodule was switched back to the `develop` branch before later pointer updates (`90fa44b6`, `57adce8`, `3e7dda0`, `31348f9f`, `b61ea536`, `e06a47ed`).
- XerahS: `Directory.Build.props` was updated to `0.21.0`, which is why the later recording and launch-policy commits moved from the older `v0.20.18` prefix to `v0.21.0` in the main repo history (`c7a74ee2`).
