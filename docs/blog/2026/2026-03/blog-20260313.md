# XerahS Daily Blog Draft - 2026-03-13

Date: 2026-03-13
Time Zone: UTC+8
Status: Draft

## Summary

Today's work consolidated two areas that had been causing churn: the `ShareX.VideoEditor` build path was tightened around the Vite 8 upgrade, and `ShareX.ImageEditor` became the source of truth for shared typography and icon semantics so both XerahS and ShareX can follow the same UI contract. XerahS also restored History thumbnail rendering by rebinding the History views to the loaded item collection.

## Features

- Added shared `ShareX.ImageEditor` typography resources and semantic icon aliases so host apps can consume one font and icon contract instead of hardcoding Lucide glyphs or local font families.
- Migrated XerahS shell, RegionCapture, and common monospace surfaces to the ImageEditor-owned `ShareX.*` resources, which reduces the cost of future font or icon swaps.
- Documented the new `ShareX.VideoEditor` frontend prerequisite in the main and developer setup guides so the Vite 8 requirement is visible before contributors hit the build step.

## Fixes

- Restored XerahS History thumbnails by binding both History list controls back to `HistoryItems`, which matches the data already being loaded and preprocessed by the view model.
- Replaced raw editor glyph codepoints in `ShareX.ImageEditor` with semantic icon mappings so shared editor chrome can evolve without sweeping host-side XAML changes.
- Kept the embedded frontend build host-safe by carrying forward the npm.cmd invocation fix that landed before the Vite 8 requirement update.
- Recorded the `node_modules` cleanup lesson for `ENOTEMPTY` failures so repeated npm bootstrap issues are easier to recover from during local builds.

## Build and Tooling

- Upgraded ShareX.VideoEditor from Vite 7 to Vite 8 and pinned the frontend Node.js requirement to ^20.19.0 or >=22.12.0.
- Added a backend build-time Node.js version check in `ShareX.VideoEditor.csproj` before `BuildWebUI`, which makes unsupported Node versions fail fast with an explicit Vite 8 message.
- Refreshed the frontend lockfile to match the Vite 8 dependency graph and the new build/runtime tooling it brings in.
- Fast-forwarded `develop` in `ShareX.ImageEditor`, XerahS, and ShareX so the shared theme-contract change is available from the default branch in all three repos.
