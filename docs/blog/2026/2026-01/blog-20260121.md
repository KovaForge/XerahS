## Summary

Pushed XerahS 0.5.0 over the line with a big UX pass around color picking, QR tooling, index-folder previews, and WebView-based HTML rendering. App lifecycle behaviour improved with single-instance enforcement and a configurable capture/recording start delay, making the app feel more polished and predictable.

## Features

- Introduced rich color tooling including dedicated color picker tools, a `ColorToNameConverter`, and standard color-name mappings, along with improved tooltips for more understandable color workflows.
- Added QR code tools, expanding XerahS’ post-processing toolbox for sharing encoded data directly.
- Modernized index-folder workflows with an index folder preview, a dedicated workflow panel, HTML rendering enabled by default, and a re-ordered action layout to make the flow more discoverable.
- Switched index-folder HTML rendering to a WebView.Avalonia-based pipeline, requiring the desktop WebView runtime but enabling a more modern, embedded preview experience.
- Improved core app behaviour with single-instance enforcement and a configurable capture/recording start delay to avoid accidental or premature recordings.

## Fixes

- Polished HTML index output with corrected indentation and render behaviour, improving readability of generated pages.
- Refined UI details like tooltip placement in `ColorPickerDialog` and always-visible render actions, smoothing out rough edges in the new workflows.

## Build and Tooling

- Bumped the app version to 0.5.0 and documented the new features and UX passes so release notes stay in sync with the code.
- Constrained WebView resolution to WebView.Avalonia explicitly, reducing ambiguity and dependency resolution issues across environments.
- Merged the `develop` branch via PR #45 to consolidate recent feature work into the main line.
