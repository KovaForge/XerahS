## Summary

January 27 was a marathon day of architecting, stabilizing, and releasing. XerahS officially cut the v0.5.1 and v0.5.2 releases, highlighted by a major redesign of the FFmpeg downloader with real-time UI progress hooks. In the same shift, the `ShareX.ImageEditor` library underwent a top-to-bottom refactor that replaced historical singletons with a modern, predictable configuration system. The day concluded with the arrival of a new `verify-recording` CLI tool to automate screen capture validation on CI.

## Features

- XerahS: Launched the `verify-recording` CLI command, enabling robust automated verification of screen recording output in cross-platform pipelines (`732e1735`).
- XerahS: Introduced a sophisticated FFmpeg downloader UI with integrated progress hooks, providing a much friendlier UX for users installing dependency binaries (`1646cbb0`, `7677ceb2`).
- ShareX.ImageEditor: Introduced a central `EditorOptions` system to manage editor state, replacing several ad-hoc singleton patterns and enabling predictable view model synchronization (`5474a7a2`, `449556da`).
- ShareX.ImageEditor: Added specialized stroke width and transparent fill support for the speech balloon tool, further extending its versatility (`b0f4cf2d`, `cccfede7`).

## Fixes

- XerahS: Relocated Windows-specific P/Invoke types to `Platform.Windows`, improving the project's platform abstraction layer (`90da89af`).
- XerahS: Aligned FFmpeg download paths and CLI naming conventions to match project standards across all platforms (`b4fdcbf1`).
- ShareX.ImageEditor: Significantly improved crop handling and history management, resolving several state-sync issues during complex editing sessions (`4e1fc9cf`).
- ShareX.ImageEditor: Resolved coordinate math errors in the arrow annotation tool by shifting to a geometry-based path generation strategy (`a622384e`, `eebf982f`).

## Build and Tooling

- XerahS: Published the detailed release notes for the v0.5.1 and v0.5.2 milestones into the repository changelog (`0eae9951`).
- ShareX.ImageEditor: Cleaned up the library core by removing redundant `App.axaml` entry points that are no longer required in the library-only mode (`6b4b2f42`).
