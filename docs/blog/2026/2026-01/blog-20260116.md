## Summary

Region capture took center stage with a new DPI-aware `XerahS.RegionCapture` project and several performance and correctness improvements across the selection pipeline. This was the day where region capture stopped being a side-effect of other systems and became a dedicated, well-shaped feature in its own right.

## Features

- Introduced the `XerahS.RegionCapture` project with DPI-aware region capture, providing a dedicated and scalable foundation for future capture features across multi-monitor setups.
- Added a `compare-capture` CLI command so scripted and headless workflows can verify capture output programmatically, opening the door to automated regression checks for visuals.
- Refined region capture selection and overlay rendering so the selection rectangle, dimming, and crosshair feel more polished and responsive.

## Fixes

- Aligned the region capture implementation with the overlay service, ensuring that overlay state and capture state stay in sync even under rapid interactions.
- Fixed window positioning to use physical (rather than logical) coordinates so region capture behaves correctly on high-DPI and mixed-DPI monitor configurations.
- Improved window refresh and region dimming performance, reducing flicker and latency during selection drags.
- Refactored selection handling to use `SKRect` instead of `SKRectI`, improving precision and consistency in drawing and hit-testing.

## Build and Tooling

- Merged the region capture work via a dedicated pull request, keeping the history clear and ensuring the new project and command wiring land together.
