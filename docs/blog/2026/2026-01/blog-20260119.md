## Summary

Deep capture and workflow reliability dominated today’s work: macOS ScreenCaptureKit was fully integrated, FFmpeg and native library path handling were centralized, and cursor visibility issues during capture were resolved. The image effect pipeline and presets saw another refinement pass, and the version was bumped to 0.4.0 with matching changelog updates and more modular agent documentation.

## Features

- Integrated native macOS ScreenCaptureKit support into the core capture pipeline, bringing macOS recording much closer to parity with other platforms.
- Improved recording stop flow (including macOS-specific handling) to make stopping recordings more reliable and user-friendly.
- Enhanced image effects handling with refactored preset management, improved UI, and better effect naming and cloning behaviour.
- Introduced custom JSON converters such as `SkColorJsonConverter` to make complex types serializable in a more robust and predictable way across workflows.

## Fixes

- Centralized FFmpeg path resolution in `PathsManager` and refined native library handling, improving portability and correctness of recording backends across environments.
- Added macOS native libraries to the CLI project and applied minor fixes to ensure the native pipeline works end-to-end outside the GUI.
- Fixed multiple cursor-related issues during capture by tracking selection cursors correctly, hiding system cursors during capture, and hiding the live cursor in GDI capture.

## Build and Tooling

- Refactored and modularized agent and developer documentation to make it easier for both humans and automation to follow the intended workflow.
- Bumped the version to 0.4.0 and updated the changelog to reflect the ScreenCaptureKit, FFmpeg, and effect pipeline changes.
- Merged PR #43 to bring cursor-handling and capture fixes together under a reviewed change set.
