## Summary
June 6, 2026 focused on correcting how the onboarding flow stores OCR language choices in XerahS. The main product change preserves the full multi-select language list instead of silently collapsing it to a single primary language, and the follow-up documentation commit recorded that fix in the repo's tracker/state artifacts.

## Features

- XerahS now retains the full OCR onboarding language selection in `OCROptions.PreferredLanguages` so future multi-language UI work can recover every user choice instead of only the primary language.

## Fixes

- Fixed an onboarding persistence bug where only the first selected OCR language survived commit time even when the user chose multiple languages.
- Kept `OCROptions.Language` as the primary runtime language while storing the complete selection list separately, avoiding data loss without changing the current single-language OCR execution path.

## Build and Tooling

- Added four regression tests in `OnboardingWizardCommitSettingsTests` to cover multi-select round-trip, single-select round-trip, skipped OCR steps, and empty OCR language lists.
- Updated the hourly review tracker and state files so the persistence fix is documented in the repository's ongoing maintenance record.

## Notes

- The OCR runtime still processes one language per `RecognizeAsync` call today, so the new persistence work is primarily about preserving user intent until a broader multi-language picker or execution flow is implemented.
