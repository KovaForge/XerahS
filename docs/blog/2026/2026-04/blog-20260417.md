# XerahS Daily Blog Draft - 2026-04-17

Date: 2026-04-17

Status: Draft

## Summary

2026-04-17 focused on stabilizing plugin deployment on `develop`, especially around keeping plugin installs isolated by architecture and making the migration path safer for existing user data. The work also tightened manifest parsing so legacy plugin metadata is still recognised during migration, then advanced the `ShareX.VideoEditor` submodule to a newer revision for downstream integration.

## Features

- XerahS: Plugin discovery and loading now look in architecture-specific user plugin folders, which gives `win-x64`, `win-arm64`, and `win-x86` installs separate storage instead of mixing plugin payloads in one shared directory.
- XerahS: Legacy plugin folders in the user profile are now migrated into the matching architecture folder automatically, with conflict handling that preserves existing copies instead of overwriting them silently.

## Fixes

- XerahS: Plugin loading now validates configuration and lookup paths against the active architecture so an incompatible plugin build is less likely to be loaded into the current desktop runtime.
- XerahS: Migration manifest parsing was corrected to read plugin JSON properties case-insensitively, which protects plugin upgrades when manifests use lower-case field names such as `pluginId` or `assemblyFileName`.
- XerahS: The plugin migration flow now falls back to scanning available DLLs when the manifest does not provide a direct assembly file name, reducing the chance of abandoned legacy plugin folders.

## Build and Tooling

- XerahS: `Directory.Build.props` was bumped to version `0.22.3` as part of the plugin architecture separation and migration fixes landing on `develop`.
- XerahS: `docs/architecture/xerahs_architecture_map.md` was updated alongside the plugin-system changes so the repository documentation reflects the new architecture-aware plugin layout.
- XerahS: The `ShareX.VideoEditor` submodule pointer was advanced to commit `70ac366`, recording a newer upstream dependency snapshot in the desktop app repository.
