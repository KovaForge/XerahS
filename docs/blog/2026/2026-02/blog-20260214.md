Date: 2026-02-14

## Summary

XerahS focused on unlocking a new MAUI-based mobile surface, dramatically expanding the app footprint beyond desktop while keeping the Avalonia UI as the shared backbone. At the same time, the team landed an async streaming indexer, improved Region Capture and annotation performance, and unified annotation visuals between the main app and the `ShareX.ImageEditor` submodule to keep capture and editor experiences consistent.

## Features

- **XerahS: Add MAUI mobile project and mobile documentation**: Introduced a MAUI-based mobile project tied into the existing solution, including README and developer docs updates that describe the mobile implementation and development workflow (`493d1476`, `6ae514cd`, `4d03efd8`, `59e306c5`, `8007b39b`, `90a894c6`, `d90f593d`).
- **XerahS: Async streaming indexer with filters**: Implemented an async streaming indexer with progress reporting and cancellation support, plus new include/exclude file extension filters so large libraries can be scanned more efficiently and selectively (`8b2fe880`, `e3445f5b`).
- **XerahS: Workflow plumbing improvements**: Completed end-to-end wiring for workflow types and ensured the `OpenScreenshotsFolder` workflow opens directories correctly, tightening the link between capture actions and post-capture flows (`47ead0be`, `60bbaf22`).
- **ShareX.ImageEditor: Theme-aware editor and Avalonia integration**: Refined Avalonia integration, made the editor view follow app theme resources, and ensured the editor window behavior feels natural when loading images, so the embedded editor in XerahS behaves like a first-class, themed surface (`ce75b24`, `987b3d5`, `5068121`, `54b7070`, `6e4f7aa`, `72c0425`, `9468511`, `64d95b3`, `5093d33`, `5112d21`, `6715dff`).

## Fixes

- **XerahS: Region Capture and annotation performance**: Optimized Region Capture annotation rendering, removed the draw-start dot artifact, and improved overlay drawing responsiveness by switching the annotation overlay to Avalonia visuals and aligning it with the ImageEditor geometry (`891eed09`, `faa84e75`, `d1afa2fc`, `1546876c`, `cc074adf`).
- **XerahS & ShareX.ImageEditor: Arrow geometry correctness**: Fixed arrow geometry by sharing a common `ComputeArrowPoints()` approach between the overlay and ImageEditor, ensuring arrows render consistently across the editor and capture overlay (`bec92532`, `4e45fb0`, `fbdcd2c`, `a9368af`).
- **XerahS: Capture and workflow polish**: Preserved the `ShowAfterCaptureWindow` flag in the after-capture dialog, hid the SilentRun window on first open, and fully wired workflows like Amazon S3 setup steps and directory opening to avoid unexpected UI states or misaligned configuration flows (`a8262d43`, `7567223a`, `3196b02a`, `47ead0be`, `60bbaf22`).
- **XerahS: Update checker robustness**: Hardened the update checker so repositories that only publish pre-releases are handled gracefully without confusing version results (`ed68066f`).
- **ShareX.ImageEditor: Theming and resource fixes**: Polyfilled missing theme resources and fixed invisible controls so the editor looks correct when hosted inside XerahS with the app’s theme and resource dictionaries (`af0d13d`).
- **ShareX.ImageEditor: ShareX compatibility**: Added .NET 9 multi-targeting for ImageEditor to stay compatible with the ShareX app while XerahS tracks the develop branch (`cd4f62f`, `5ec0315`, `cd4f62f`).

## Build and Tooling

- **XerahS: Integrate MAUI branch into develop**: Merged the experimental MAUI branch into `develop`, wired it into the changelog, and updated documentation so mobile work is part of the mainline development flow instead of a long-lived experiment (`56b8e044`, `90a894c6`, `6ae514cd`, `4d03efd8`).
- **XerahS: Avalonia and ImageEditor submodule upgrades**: Bumped Avalonia packages to `11.3.12` and enforced the ImageEditor submodule to stay on the latest `develop` branch so UI behavior and editor capabilities track upstream changes predictably (`27ce502d`, `5e8eee09`, `e03ec125`, `71601eee`).
- **XerahS: Plugin build reliability**: Updated plugin verification to expect exactly three files, centralized the plugin copy target, and ensured the host target framework is passed so plugin builds are deterministic and aligned with the app’s TFM (`d567b313`, `6bfa2e11`).
- **XerahS: Documentation and UI audit**: Refreshed the UI control audit snapshots and expanded developer- and user-facing docs to cover mobile scenarios, keeping the written guidance in sync with the new MAUI surface and indexer features (`aadfea40`, `4d03efd8`, `59e306c5`, `8007b39b`, `90a894c6`, `d90a894c6`).
- **ShareX.ImageEditor: Platform and build configuration**: Restricted platforms to x64 and ARM64, added a shared `Directory.Build.props`, and tightened Avalonia package references so ImageEditor’s build matrix matches the platforms XerahS intends to support (`5093d33`, `64d95b3`, `9468511`, `72c0425`).

## Notes

- **MAUI mobile integration risk**: The MAUI mobile surface has just been merged into `develop`, so follow-up work is expected around platform-specific quirks, mobile input, and ensuring parity with the desktop capture and upload flows.
- **Indexer streaming behavior**: The async streaming indexer introduces cancellation and progress reporting paths that should be exercised on large and slow storage backends to confirm there are no starvation or starvation-related regressions.
- **Annotation and editor coupling**: With annotation visuals now unified between XerahS and `ShareX.ImageEditor`, future editor refactors need to account for the overlay integration to avoid drift between capture overlays and the full editor experience.
- **Submodule branch tracking**: XerahS currently expects `ShareX.ImageEditor` to track the latest `develop` branch; any force-pushes or history rewrites there could disrupt reproducible builds and should be avoided.
