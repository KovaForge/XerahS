# XerahS Daily Blog Draft - 2026-02-03

Date: 2026-02-03
Time Zone: UTC+8
Status: Draft

## Summary

XerahS spent the day landing Linux desktop improvements, renaming the editor integration to the new `XerahS.Editor` name across repos, and tightening up the Release build and plugin packaging pipeline. The changes collectively make the Linux experience more native (with dark mode and Wayland/Hyprland support) while preparing the solution and docs for the standalone editor repository.

## Features

- **XerahS: Linux dark mode and theme settings**: Added Linux dark mode support and theme settings so the app can follow or override the system appearance on modern desktop environments (`aa8dc04a`).
- **XerahS: Wayland/Hyprland screenshot support**: Implemented Wayland/Hyprland screenshot capture using the `grim` + `slurp` tooling combination, giving users on these compositors a first-class capture path instead of relying on X11 fallbacks (`51edcd34`, `2b9d1da5`, `458934d7`).

## Fixes

- **XerahS: Portal diagnostics and fallbacks**: Added portal diagnostics and screenshot fallbacks on Linux so when the primary capture path fails, the app can gracefully fall back and surface useful information instead of silently failing (`1c5a8870`).
- **XerahS: Plugin build reliability**: Fixed plugin build errors by improving the plugin copy target and ensuring packaging is repeatable across configurations (`a9b5c631`, `09222ccb`).
- **XerahS: Release build correctness**: Fixed Release build failures by making the `Audits.Tool` reference conditional so audit tooling is available where needed without breaking production builds (`46190a53`).

## Build and Tooling

- **XerahS: Editor rename and references**: Updated build files, docs, and project references to rename the embedded editor from `ShareX.Editor` to `XerahS.Editor`, aligning the solution and documentation with the new editor repository (`d0d12660`, `90b9fe0f`, `1dfeb3bc`, `25135d01`, `53d5307`, `fed75ef`).
- **XerahS: Packaging and versioning for v0.7.7**: Updated version numbers, adjusted build and packaging configuration, and refreshed the changelog to prepare the `v0.7.7` release (`2a8f7b42`, `42b5c096`, `09222ccb`).
- **XerahS: Git hygiene and templates**: Updated `.gitignore` and added GitHub issue templates (including a dedicated bug report workflow) to streamline contributor onboarding and keep the repository clean (`cf1cc351`, `b107da90`, `5c03c334`).
- **XerahS & XerahS.Editor: Repository split**: Renamed the `ShareX.Editor` repository and namespace to `XerahS.Editor`, with matching reference updates in the main app and the editor repo so the split is coherent across code, build, and documentation (`d0d12660`, `90b9fe0f`, `1dfeb3bc`, `25135d01`, `53d5307`, `fed75ef`).
- **XerahS: Community PR integration**: Merged community pull requests for Linux dark mode support, Wayland/Hyprland screenshot support, and other improvements, keeping `develop` current while preserving contributor attribution (`0d4742f2`, `c437389d`, `2b9d1da5`, `458934d7`, `aa8dc04a`, `51edcd34`).

## Notes

- **Linux capture expectations**: The new Wayland/Hyprland and dark mode support rely on specific external tooling (like `grim` and `slurp`) and portal behavior, so distro-level differences should be tested to confirm the diagnostics and fallbacks are sufficient.
- **Editor repo split**: With the editor now living as `XerahS.Editor`, future refactors need to be coordinated between the main app and the editor repo to avoid namespace or packaging drift.
- **Release pipeline hardening**: The `v0.7.7` release preparation surfaced subtle Release-only issues (like the `Audits.Tool` reference); it’s worth expanding CI coverage for Release and plugin packaging scenarios so these regressions are caught earlier.
